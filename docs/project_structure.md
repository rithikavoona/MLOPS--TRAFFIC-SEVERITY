│           ├── severity_model.py  Evaluation and scenario prediction form
│           └── pipeline_health.py Data lineage, quality and weather status

`data/cleaned` contains validated records before collision-level enrichment; `data/processed` is the analytical/model layer used by Streamlit. Raw input files never become dashboard inputs. Persisted layers are generated by code, not edited manually.

Source modules are grouped by responsibility without nested packages that add little value to this project. Keep entry points thin and share paths/code mappings through `src/config.py`. Generated files are separated from application code. Root `mlflow.db` and `mlruns` remain together to preserve the verified registry's stored artifact paths; they are runtime outputs, not source files.

Each dashboard page exposes `render(context)`. `application.py` owns the existing seven-tab navigation and supplies a `DashboardContext`; pages do not read variables from `app.py`. The dashboard data module owns processed artifact I/O with modification-time cache keys. Scenario inference uses `api_client.py` to call FastAPI; only the API loads the model bundle. ETL and training are separate CLI operations. Add a new page module and register its renderer in `pages/__init__.py` to extend the dashboard.

Local `.deps`, `.venv`, Python caches and PDF previews are excluded from the downloadable ZIP. `scripts/package_project.py` lives inside the project so packaging is reproducible after extraction. MLflow archives may contain absolute original-machine artifact URIs: for a portable registry, retrack the included evaluated model with `python -m src.tracking` from the extracted folder. The API uses the portable `models/severity.joblib` bundle.
