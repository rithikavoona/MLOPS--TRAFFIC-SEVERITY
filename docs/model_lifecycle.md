# Model lifecycle and retraining policy

1. Ingest the public source files and run staged ETL. Preserve raw checksums, schema, quality checks, rejection reasons and dates. Reject a training candidate if its target/key/date checks fail.
2. Generate the feature allowlist from the processed mart. Split chronologically: earlier years train, penultimate year selects parameters, latest year remains held out. Fit imputation/encoding on training rows only. Sampling is capped and reported explicitly.
3. Compare each candidate with the majority baseline using macro-F1 and per-class recall; retain the confusion matrix. The current model has weak fatal recall/precision and remains a research prototype.
4. Track parameters, metrics and artifacts with MLflow. Retain timestamped local bundles and registered versions. The source/data hash associates evaluation with its inputs. The dashboard and API load `models/severity.joblib`.
5. Promotion requires review of class recalls, false negatives, data quality and intended use. Registration does not imply production readiness. Current local training writes the latest bundle automatically; do not run training directly against an active production model mount. Stage an approved bundle before replacing the served file and restart the service.
6. Run `python -m src.monitor --batch <new-labeled-processed-batch.parquet>`. Unlabeled batches support input/location drift; class drift, recalls, macro-F1 and severe false negatives require outcomes. Full-data demonstration results overlap training and are not held-out evidence.
7. Initial review thresholds in `src/monitor.py`: categorical/location total variation >0.15, class variation >0.10, severe false-negative rate >0.40, fatal recall <0.40, feature missingness >0.20, service failure rate >0.05 or p95 latency >1,000 ms. These heuristics trigger review, not automatic retraining or model promotion. Tune them using prospective data and domain requirements.
8. HTTP request telemetry includes validation failures, unavailable-model responses and inference errors. Prediction payload logs are distinct from service-health logs. Small test-request samples do not establish a service SLA.
9. On an actionable review, validate new labels, retrain a candidate with the same reproducible command, compare temporal and geographical performance, and re-register after acceptance. Never repeatedly tune on the retained test set; define a fresh forward evaluation window as releases arrive.
10. Rollback: select a previously evaluated timestamped bundle, copy it to the served artifact location and restart the API/dashboard. Record which version was activated and why. A registry exported from this machine can contain absolute artifact paths; retracking the included local bundle creates a portable local experiment after extraction.

The local Docker deployment was built and verified on 15 October 2026; evidence is in `docs/evidence/deployment/docker_verification.json`. The scheduled Airflow runtime still requires deployment verification. Local container operation does not establish production readiness, model quality or operational monitoring performance.
